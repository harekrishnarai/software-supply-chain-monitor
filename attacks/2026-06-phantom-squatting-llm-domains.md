# Phantom Squatting — AI-Hallucinated Domains Weaponized as Software Supply Chain Vector

**Date:** June 2026
**Ecosystem:** LLM / Agentic AI / Web Infrastructure
**Severity:** High
**Type:** Domain Squatting / Phishing / Malware Delivery / C2 Infrastructure
**Sources:**
- [Unit 42 — Phantom Squatting: AI-Hallucinated Domains as a Software Supply Chain Vector](https://unit42.paloaltonetworks.com/phantom-squatting-hallucinated-web-domains/)

---

## Summary

Unit 42 researchers documented a novel supply chain attack vector they call **phantom squatting**: large language models consistently hallucinate web domains for legitimate brands, and adversaries are actively registering these non-existent domains to intercept traffic generated by AI systems. The research analyzed 2.1 million unique URLs generated by two production LLMs against a corpus of 913 global brands (685,339 prompts total), finding that **37.28% — roughly 809,000 URLs — resolved to non-existent domains (NXDs)**, representing approximately 250,000 unique registerable phantom domains.

Phantom squatting extends the logic of *slopsquatting* (where LLMs hallucinate package names in software registries) to web infrastructure. When an LLM produces a URL, that artifact may be ingested by autonomous AI agents making live HTTP requests, integrated by developers into production code, or included in AI-generated documentation distributed at scale — meaning the LLM itself functions as a trusted supply chain dependency. Unit 42 confirmed active exploitation in multiple real-world campaigns: malicious actors are registering phantom domains and staging phishing kits, malware droppers, and C2 infrastructure before victims even query the LLM.

Of particular concern is the adversarial exploitation window (AEW) — the time between when Unit 42 first detected a hallucinated domain and when an attacker registered it with malicious intent. In the Montana Empire case, the attacker had pre-staged the server-side phishing kit *prior* to domain registration, demonstrating an optimized zero-reputation bypass strategy that operates faster than any feasible defensive response.

## How It Worked

### Stage 1: Hallucination Surface Mapping

Attackers (or defenders in Unit 42's research pipeline) probe LLMs with high-volume queries about legitimate brands, products, and services, capturing the full set of URLs each model generates. Queries are filtered using Jaccard similarity to broaden coverage of the model's hallucination surface. This reveals a predictable set of phantom domains that any user of the same model will likely receive when asking similar questions.

### Stage 2: Domain Registration

Phantom domains are cheap and fast to register. For generic TLDs, registration is economical and nearly instantaneous. Threat actors operate with significant speed — in observed telemetry, domains transitioned from initial registration to active malicious content deployment **within hours**. The Montana Empire actor had pre-staged its phishing kit server-side before the domain was even registered, achieving near-zero AEW for defenders.

### Stage 3: Weaponization

Registered phantom domains host:
- Drive-by malware droppers and exploit kits (67.2% of malicious cases)
- Credential-harvesting phishing portals impersonating the legitimate brand (16.2%)
- C2 endpoints that can receive connections from autonomous AI agents (3.0%)

The C2 vector is especially dangerous: if an agentic AI system follows an LLM-generated URL as part of its task execution, it may send sensitive context or receive instructions from attacker infrastructure with no human in the loop.

### Stage 4: LLM as Attack Delivery Mechanism

Following domain weaponization, the LLM itself acts as the primary delivery mechanism. Any user or autonomous AI agent that queries the model receives a high-confidence recommendation to navigate to the attacker-controlled endpoint. The LLM presents the phantom domain as the authoritative resource for a trusted brand, with no disclaimer that the domain may be fictitious.

## Remediation

1. **Never trust LLM-generated URLs without validation**: Treat all URLs produced by LLMs as untrusted input. Resolve the domain, verify it belongs to the expected brand, and check it against threat intelligence before use.
2. **Implement agentic URL allowlisting**: For autonomous AI agents that make HTTP requests, enforce a strict allowlist of known-good domains. Block or require human approval for any URL not on the list.
3. **Audit AI-generated code before deployment**: Any URL, API endpoint, or SDK download link appearing in AI-generated code should be manually verified against official brand documentation.
4. **Use real-time URL threat intelligence**: Palo Alto's Advanced URL Filtering and Advanced DNS Security identify known phantom domains associated with this research. Integrate a URL reputation feed into AI agent HTTP clients.
5. **Monitor AI agent network traffic**: Log all outbound HTTP/HTTPS requests made by AI systems and alert on connections to domains registered within the last 30 days.
6. **Add hallucination guardrails to LLM pipelines**: Where possible, validate model-generated URLs using a tool call or retrieval step before returning them to users or agents. Ground URL generation in a verified knowledge base of official brand domains.
7. **Treat AI agents as network-active processes**: Apply the same egress controls, proxy inspection, and network segmentation to AI agents that you apply to untrusted user-facing applications.

## Lessons Learned

- **LLMs are now a supply chain component**: When AI models consistently hallucinate the same phantom domains, they function as a systematic and exploitable dependency in the software supply chain — not merely an occasional source of incorrect output.
- **The adversarial exploitation window can be near-zero**: Attackers who pre-stage infrastructure before registering phantom domains can be ahead of any defender. Proactive monitoring of hallucination surfaces is required, not reactive takedowns.
- **C2 via AI hallucination is a novel and serious threat**: 3% of confirmed malicious phantom domains host command-and-control infrastructure. An agentic AI following a hallucinated URL could send sensitive data to or receive commands from attacker infrastructure with no user interaction.
- **Hallucination rates differ dramatically by model**: LLM1 (enterprise mini-class) hallucinated at 44.6% vs LLM2's 27.5% — but both exhibited similar rates of actively malicious phantom domains (~0.6%). Cost-optimized models deployed at scale create disproportionate hallucination volume.
- **Slopsquatting extended to the web layer**: The same logic that made hallucinated package names dangerous in npm/PyPI (attackers register what models invent) now applies to web domains. The attack surface is orders of magnitude larger — ~250,000 registerable phantom domains vs. hundreds of hallucinated package names.
